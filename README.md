# HERACLES DAILY

移动端优先的每日恢复与训练准备度规则引擎。粘贴 HRV、睡眠、静息心率、ATL/CTL 与训练记录后，网页会在当前浏览器内计算三项准备度，并给出唯一主要训练方案。

这是纯前端静态应用：不调用 AI，不上传训练数据，不需要账号、数据库或服务器密钥。

## 开源协议

本项目采用 MIT License。你可以学习、修改、分发和二次开发，但训练建议仅供一般信息与自我管理参考，不构成医疗诊断。

## 已实现

- Recovery = HRV 40% + Sleep 35% + RHR 25%
- Readiness = Recovery 50% + Load 30% + Structure 20%
- 首页三项核心评分：Recovery / Strength Readiness / Aerobic Readiness
- 第一屏只保留三项准备度、今日建议、首选项目与关键限制
- Key Limiter 自动提取当天最重要限制因素
- Form、ACWR、ATL Spike、Fatigue Momentum 自动计算
- Neural Limited / CNS Fatigue、疼痛和急性症状硬性封顶
- 缺失值显示 Unknown，剩余可用权重自动归一化
- 支持整段粘贴 HERACLES DAILY 报告并自动识别填表
- 粘贴后显示“已识别字段 / 缺失字段”，不再静默失败
- 粘贴后可在 30 秒内补充疼痛、症状、精神状态与局部酸痛
- 推荐训练、RPE、时长、动作、组次与重量集中在同一方案板块
- 同部位力量刺激 48 小时内不重复推荐
- 高强度/冲刺骑行结束后48小时暂缓腿力量与强骑；腿力量后的36小时交叉限制继续保留
- 独立展示骑行专项准备度、骑行时长、sRPE负荷、功率/心率高区分钟数与恢复窗口
- 手动输入与计算审计默认折叠，需要时再展开
- 数据仅保存在当前设备浏览器
- 一键导出 1080×1920 今日报告图片，内容与网页三项准备度逻辑一致
- 骑行、力量、游泳、拳击分别输出对应训练细案
- 支持安装到 iPhone / iPad 主屏幕

## v4.8 骑行与腿部恢复规则

骑行既有心肺负荷，也有腿部局部负荷，但不把骑行折算成深蹲组数。胸/背/腿的力量组数只统计力量动作。全身负荷仍沿用导入的ATL/CTL，不把骑行单独展示的负荷再次相加。

- 单次骑行负荷 = 分钟 × 整节RPE（0–10），单位AU；展示近48小时、近7日的已知负荷。缺失RPE不按0计算完整负荷，明确提示只显示已知部分。
- 功率优先：Z6–7累计≥1分钟，或Z7累计≥0.5分钟，或明确冲刺/高扭矩标签，触发48小时恢复窗口。功率Z4–7累计≥10分钟、Z5–7累计≥5分钟、整节RPE≥7或明确高强度间歇标签，也触发48小时窗口。
- 无完整功率分布时，以心率Z4–5累计≥10分钟作为保守高强度线索。心率区间不等于无氧功率区间；短冲刺不能靠平均心率可靠识别。功率区间取决于正确的FTP设置。
- 非高强度骑行单次负荷≥600 AU，暂缓腿力量与强骑24小时。近48小时已知骑行负荷≥900 AU且24小时内仍有≥150 AU的骑行，也触发累积限制；不因后续几分钟轻松转腿重置高强度窗口。
- 恢复窗口逐次计算，取尚未结束的最晚限制。计时从骑行**结束**起算，而非开始或跨过午夜；尚未结束/评估后的运动不进入本次评估。重复同一记录不多次累计。
- 强骑后48–72小时仍需下肢酸痛≤2/5、腿部疲劳选“可训练”，并通过热身RPE差<2、疼痛≤3/10、动作正常等复查；否则继续暂缓腿力量和强骑。明显下肢酸痛≥4/5或疼痛优先于计时，不因时间到而放行。
- 受限时腿部与骑行专项分数最高54（用于排课的模型上限，不是生理测量）；无冲突胸背不一并扣除局部疲劳。心肺/有氧分数仍独立保留，不能据此覆盖腿部限制。未知骑行资料未通过复查时也不自动排腿；骑行仅允许轻松强度。
- 建议标题、RPE剂量和执行步骤共用强度许可。恢复骑行不再出现3×6分钟节奏段，也不绕道推荐拳击步法/强力打腿叠加腿部高强度。

以上分钟、AU、24/48/72小时和评分上限都是**可审计的保守排课默认值，未经个体生理模型验证**，不应被解读为“所有人48小时都恢复”或“骑行等于增肌训练”。需结合个人训练基础、主观腿部疲劳、睡眠、疼痛和热身校准。重复冲刺研究观察到了24小时后仍未完全恢复的部分神经肌肉指标，但不能直接推导出每个人的固定恢复时间。

参考：Milioni F, Azevedo RA, Zagatto AM, Millet GY. *Time Course of Recovery after Cycling Repeated Sprints*. Medicine & Science in Sports & Exercise, 2021. [PubMed](https://pubmed.ncbi.nlm.nih.gov/33300757/)。

数据迁移：旧版只保存强骑次数，无法还原功率分布。升级后重新粘贴原始完整导出；保留本机原数据，不清空用户记录。没有功率或报告漏记冲刺时，可在“骑行与腿部恢复”补充强度类型及结束时间，只增加限制、不重复累加负荷。完整重新导入会清除补充项；日期切换后会提醒重新导入，避免旧数据被当作今天已恢复。

## 在 iPad 上发布到 GitHub Pages

1. 在 GitHub 新建公开仓库，建议命名为 `heracles-daily`。
2. 把本项目全部文件上传到仓库根目录。
3. 打开仓库的 `Settings → Pages`。
4. 在 `Build and deployment` 中选择 `GitHub Actions`。
5. 等待仓库上方 `Actions` 页面显示绿色完成标记。
6. 回到 `Settings → Pages`，打开生成的网址。
7. 在 Safari 分享菜单选择“添加到主屏幕”。

之后每次修改并提交代码，GitHub 会自动重新发布。
